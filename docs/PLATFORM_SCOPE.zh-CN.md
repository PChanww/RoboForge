# RoboForge 平台支持范围

RoboForge 可以为不同桌面机器人配置场景、控制器和相机。当前内置任务是双指夹爪抓取物体并放入托盘。换机器人、换物体和换任务是三种不同的改动，分别检查运行条件。

| 方面 | 当前可用 | 迁移到新配置时先确认 |
| --- | --- | --- |
| 资产生成与导入 | Lux3D 物体、静态道具、机器人外观或环境网格，World 高斯背景，以及本地 GLB/PLY 场景导入 | 资产需要明确角色、尺寸、碰撞和支撑条件。生成的机器人外观进入连杆装配流程。 |
| 机器人与控制器 | 五旋转关节机械臂和三轴直线龙门均已验证观测与动作接口。关节位置控制可按已配置的执行器名称绑定。 | 先查所选机器人的 `controller_ids`。固定姿态逆运动学对应已定义的 5R 运动链。修改运动链后要实际验证运动学。 |
| 任务与末端机构 | 支持桌面抓取、抬升和托盘放置，目标、生成位置、托盘和夹爪接触面可配置。 | 当前任务判定依赖双指夹爪和托盘接触。移动机器人、足式运动、吸盘和其他任务需要新的任务或控制实现。 |
| 图像与状态 | 执行器关节的具名位置与速度、末端与夹爪状态，以及固定或随连杆运动的 RGB 相机。 | 按所选机器人的 `sensor_ids` 检查可用相机。需要同时核对安装连杆、分辨率、坐标系、时序及运行时帧状态。Hybrid 限固定前视。 |
| 示范采集 | 内置伺服专家使用固定姿态 `cartesian_delta_ik` 执行桌面抓放，并可导出 LeRobot 数据。 | 龙门能执行自己的关节位置脚本。为龙门或其他机构批量采集，要提供与其动作契约相符的专家或采集入口。 |
| 外部模型 | HTTP、WebSocket 与 Gymnasium 提供观测和动作通道。 | 模型适配器负责张量、预处理、归一化和动作变换。通过静态绑定检查后，用真实仿真做一步检查，再验证完整任务。 |

## 已验证的机器人示例

- **默认五轴机械臂 `lux3d_5r`**。可用 `cartesian` 输出归一化末端增量，也可用 `joints` 输出五个关节角和共享夹爪位置。
- **三轴龙门 `cartesian_3dof`**。使用 `configs/second_robot.json` 中的 `joints` 控制器，动作顺序为 `[x, y, z, gripper]`，单位都是米。默认项目还列有龙门结构，但需要为它提供匹配的控制器后才能在该项目运行。可直接导入单独的 `second_robot` 项目，步骤见[模型接入指南](MODEL_INTEGRATION.zh-CN.md)。

本轮以原有的 `scripts/test_second_robot.py` 重跑 145 步。龙门执行了关节位置动作，脚本未抓起或抬升杯子。完整抓放需要针对目标机构配置并验证轨迹。

同名控制器在不同项目中可以有不同的动作顺序。获取 `/api/v1/capabilities?project=<项目ID>` 或下载该版本的项目绑定指南，读取每个机器人的 `controller_ids`、`sensor_ids` 和不可用原因。关联生成任务的指南是生成时的配置参考，应用配方后的项目指南对应真正运行的项目版本。绑定检查用于确认配置与观测、动作接口能对应。物体接触、视觉可用性和任务结果以实跑为准。
