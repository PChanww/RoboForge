## 额外发现并修复：视觉桌面没有接触

现有 `scene_demo` 配置关闭默认桌面，却没有静态碰撞体。杯子实际落到地板；三维主视图接入环境后，这个问题表现为杯子陷进视觉桌面。旧验证记录把部分失败归因为可达性，证据不足；缺少桌面碰撞是已确认的配置问题。

本次没有覆盖该原项目，而是新增 `scene_repaired_review`，使用已知演示桌面尺寸的 box 代理（全尺寸 0.8×0.6×0.05 米，中心 z=-0.025 米）。原项目保留供对照。运行时对“导入环境、关闭默认桌面、无启用碰撞体”的组合明确报错；新绑定需保留默认桌面或已有代理。

碰撞代理在有环境视觉网格时不重复绘制为不透明表面，避免共面闪烁；编辑器的“碰撞”开关显示线框。代理几何仍参加 MuJoCo 接触求解。演示墙壁目前作为视觉背景，尚未为墙壁补齐所有物理代理，不能把该例当作完整房间碰撞验证。

## 你需要审查的行为变化

- 旧的非 1 unit_scale 且没有 normalized_units 标记的资产，要求重新导入。避免猜测旧文件是否已经缩放，造成再次缩放。
- 本地网格只有在用户确认实际尺寸后才允许物理绑定；未知单位只能保留资产，不能直接运行。
- 当前杯子任务只支持工作表面 z=0；非零 work_surface_z 明确拒绝。机器人、任务、相机的通用工作坐标适配尚未完成。
- 当前视觉 CNN 支持固定 5R 基线的 18 维状态、4 维动作和 front 相机；不兼容的机器人/动作/相机会提前失败。
- 旧 LeRobot 数据集缺少 simulation.json 时需转换到新 ID，不能从名称猜测训练配置。旧模型没有 contract 时，CLI 可显式使用 --allow-legacy-contract，但会记录历史假设。
- 原“状态 BC / 特权 BC”入口仍为固定基线，界面已说明；本次参数化的是视觉流程。
- 数据转换不再递归删除已存在目录；相同采集 ID 同样拒绝覆盖。模型 ID 仍应由用户区分实验，模型版本注册可作为下一项改进。
- 生成任务需要显式查询，下载和处理在后台进行；查询中断可以重试，远端 ID 不变。提交结果未知时不自动重复提交，不能承诺跨网络/进程故障的严格 exactly-once。
- 当前 JSON 作业存储面向单后端进程。生产环境多 worker、跨机器任务、WSL 子进程可靠取消仍需 SQLite/队列/进程监督方案。

## 后续实现建议

优先顺序：

1. **独立 SensorRenderer 与 3DGS 服务。** 先做一个 front 相机的离线测试，验证指定内外参、动态网格遮挡和采样快照；关闭页面仍应能生成相同语义的观测。再接 wrist、延迟、吞吐。先固定支持的 Three/3DGS 依赖版本。
2. **工作区域与物理编辑。** 将场景详情升级为真正的三维编辑器，支持测量、标定新版本、代理绘制、桌面/墙体检查、任务与机器人锚点。自动体素/网格只生成候选代理，不能直接视为准确接触表面。
3. **训练实验与数据版本。** 增加正式的场景分组、成功示范筛选、多相机策略适配、逐帧时间戳随 LeRobot 导出、模型/数据集版本与资产哈希绑定。先把视觉 BC 基线训练充分，再评价跨场景泛化和接入真正的语言条件 VLA。
4. **任务基础设施。** 将任务索引迁移到 SQLite 或队列，补上并发、任务恢复、WSL 子进程取消和进度通知；单体 Lux3D 也统一到提供方作业接口。
