## 一次完整实验怎么做

1. **建一个可重复的对照。** 进入[任务要求](http://127.0.0.1:5173/transport?view=task)，先选「从传送带抓取并送入箱子」。在「模型资产」复用已有物品和箱体，在「参数设置」记下箱位、种子、带速和动作速度。先用 1 回合，避免同时更换几个变量。
2. **用状态专家验证场景。** 在「执行策略」选状态专家基线。返回任务页，点「检查执行方案」，确认动作顺序和路线，再点「开始仿真验证与采集」。若使用新生成的外形，到「模型资产」逐项确认保存或仅本次使用，仿真随后继续。
3. **观察、停止或保存。** 「仿真执行」显示前视／腕部画面、仿真时钟、阶段、推理次数和已经施加的动作数。需要结束时点「停止并保存」，等状态变为「实验已停止」后，在「数据集」检查帧数。长回合可能花更多时间写盘。想留档时下载单条 NPZ 或完整 ZIP。
4. **先审样本，再扩充示范。** 在「可行性结果」看任务是否通过、失败阶段和数据校验。只使用通过且数据有效的专家示范训练。变更种子、物品和箱位时记录每次改动，同任务至少留出一条独立轨迹供验证。
5. **提交 GPU 训练。** 从「数据集」点「使用本轮数据训练」或历史记录的「用此数据训练」，也可直接进[训练中心](http://127.0.0.1:5173/training)的「移动搬运」。选择模型、轨迹和轮数，提交后查看日志、训练设备、验证误差和检查点。检查点保存在 `datasets/transport_models/`。
6. **切换检查点做闭环。** 在训练中心点「用于搬运仿真」，确认策略与设备。在同一配置先对照专家，再用留出种子、物品或箱位做独立测试。在[评测](http://127.0.0.1:5173/evaluations)按检查点查任务通过、阶段、设备、实际动作和数据校验。离线误差、数据校验与物理任务结果分别看。

| 策略 | 什么时候用 |
| --- | --- |
| 状态专家基线 | 首次验证物理场景、路线和抓取，或采训练示范。 |
| SmolVLA · 移动动作头 | 用任务语言、双相机和机器人状态测试抓取到移动入箱，能输出包含底盘动作的 7 维指令。 |
| 移动双相机 BC | 比较视觉与机器人状态联合输入的行为克隆效果。 |
| 移动状态 BC | 用机器人状态和任务参数做对照，不输入相机画面。 |
| 移动特权 BC | 加入物体真实位姿和速度，检查仿真诊断上限。 |
| SmolVLA · LIBERO 实验适配 | 测试机械臂和夹爪。底盘指令恒为零，完整移动搬运选移动动作头。 |

## VLA 卡顿时怎么处理

### 最近两次实测

2026-11-19 的两条记录均在 RTX 4060 上使用 CUDA。它们运行的是「入箱取出再返程」，请求了 3 个回合。做性能复测时先改成单回合的「传送带抓取并入箱」。

| 实验 | 观测 | 处理方向 |
| --- | --- | --- |
| `transport_fdad2c80ccce44`，LIBERO | 每组执行 5 步。213 组端到端中位约 0.889 秒，95 分位约 0.994 秒。53.25 秒仿真约花 4 分钟，之后手动停止，保存 1,065 帧。 | 这是同步等待 GPU 的典型现象。做完整搬运换移动动作头。若只测 LIBERO 机械臂，在相同短任务中把每次执行步数从 5 调到 8 或 10 对比。动作组越长，重规划越少，跟随移动传送带的反应也可能变慢。 |
| `transport_4e8ae42bc45541`，移动动作头 `ca6b3010d8f0` | 每步都推理。251 次调用的端到端中位约 67 ms，95 分位约 84 ms。执行了 250 步、12.50 秒仿真，最后目标 0.4607 m 超出 0.4600 m 可达限值。最后记录的前视画面有效。 | 页面走得慢是因为单次等待已超过 20 Hz 的 50 ms 仿真步长。这个检查点固定每次输出 1 步，调大网页的每次执行步数不会加速。越界属于策略失败，在评测里查失败阶段，增加等待时间无法处理。 |

| 看到什么 | 先做什么 |
| --- | --- |
| 「连接失败」或启动方案一直提交 | 核对 C 盘空间，检查下方三个端口。后端报 507 时先回收旧失败输出或可重新生成的 ZIP，再刷新重连。 |

## 接下来怎么做

**你要做的。** 先按上述流程做单回合对照，顺序为「专家基线 → SmolVLA 移动动作头」。先保持场景、箱位、速度和种子一致。记录两个实验 ID，以及卡住时页面显示的阶段、仿真时间和动作数。专家通过后，再收集不同种子、箱位和物品的成功示范。训练时留出完整回合，测得稳定结果后再改成多回合采集。

**后续开发的顺序。** 先用相同留出场景复现目标越界和偶发相机错帧。为学习策略增加显式的可达性处理，记录模型原始指令、约束后的指令和实际施加动作，保持成功判定独立。再对单步移动动作头拆分计时，分别测图像编码、推理、相机渲染和写盘。根据结果评估降低每步开销或引入由模型产生的动作块，使用同一留出集对比延迟、停止响应和任务通过率。最后扩大多物品、多箱位和顺序任务的评测范围。

## 产品目标

用户描述环境、机器人、物品与任务，确认生成模型后，在真实物理仿真中检查任务可行性，保存可追溯的成功／失败数据，为 VLA 的训练、接入与闭环评估提供依据。模型生成、专家基线通过和 VLA 策略通过分别报告。

后端已有 MuJoCo、相机与动作接口、视觉 BC 训练评估、LeRobot 转换和策略契约检查。移动任务可选择状态专家基线、公开 LIBERO 适配或本地移动策略检查点，记录实际执行来源、动作和结果。移动 SmolVLA 使用冻结的图像及语言编码，训练本机器人的 7 维动作头。服务就绪、样本有效与模型完成任务分别验收。

## 顺序任务与物理完成条件

当前支持四类明确的任务程序；文字检查将识别到的完整动作顺序列在方案中，超出范围的动作应先报告，不能静默省略。

| 任务 | `task_kind` | 执行与终点 |
| --- | --- | --- |
| 从传送带抓取并送入箱子 | `deliver` | 抓取、抬升、轮地驱动到箱旁、受控松爪、稳定入箱 |
| 拿起来后原位放回 | `pick_return` | 抓起后放回首次抓取点的世界坐标，确认传送带支撑并撤爪 |
| 放入箱子后再拿出来 | `bin_retrieve` | 完成入箱，再次双侧夹持，抬出箱沿并稳定保持；结束时仍夹持物品 |
| 入箱、取出，再沿原路放回 | `bin_return` | 入箱、再次抓取、抬出、收臂、沿反向航点路线返回、原抓取点受控释放与撤爪 |

传送带持续运行。“原位”指首次实际抓取的世界 XY 坐标；放回后物品继续随传送带移动。顺序任务不会在第一次入箱时提前判为整条任务成功。再抓取必须有真实双侧接触；箱内取出要求物品最低点越过箱沿并稳定夹持；放回要求实际滚筒接触、稳定支撑、松爪并撤离。搬运与返程通过轮地接触驱动，运行期不写入物品／底盘自由刚体位姿，也不添加焊接约束。

专家基线读取仿真真值并执行这些步骤；VLA 模式的动作由模型服务给出，物理观察器独立判断实际完成事件。专家程序不会补做 VLA 未完成的步骤。

## 模型确认与保存

新模型生成后暂停，不启动仿真。用户逐个选择保存到本地资产库、仅本次使用或放弃本轮。所有角色确认后才继续；刷新和重启不会代替用户作答，不重新提交生成。

生成必须有本地缓存用于导入与预览；缓存不等于正式入库。显式保存后可在后续任务复用；仅本次使用的模型保留该次实验的来源记录，不自动加入复用列表。模型包包含原GLB、导入OBJ、清单及本任务参数。旧资产与历史失败数据保留；原生成工作台仍沿原行为运行。

## 可行性与数据

报告读取实际保存的数据，显示本次执行策略、是否通过、各子任务完成证据、失败阶段、最后双侧夹持时间、阶段时间线与数据检查。单次成功仅说明当前策略、资产、参数和种子的实验通过；专家通过不能证明 VLA 通过。中断、停止、待确认和执行失败分别显示。

数据检查覆盖动作维度／范围、有限数值、20Hz递增、相机形状与RGB类型、配置SHA-256和成功标签一致性。采集前必须核对双相机的成功状态、采集时间与机器人状态时间一致；缺少采集证据、报错或过期画面会停止，不能复用旧画面充当当前帧。若动作施加后下一次渲染失败，已完成的状态、画面与动作配对仍保存。失败数据保留，训练前按标签筛选。完整包包含原NPZ、配置、清单、报告与策略契约。

策略输入契约包含任务语言、前视／腕部 RGB 和28维机器人状态（7维机械臂关节、7维底盘位姿、6维底盘速度、4维轮角、4维轮速），另提供由机器人运动学测量的底盘局部末端位置与夹爪开度。物品真值位姿、接触与成功判定仅作为监督和评估注释，不发送给 VLA。

动作协议为 `mobile7_v1`：`[arm_x, arm_y, arm_z, gripper, base_linear_m_s, base_angular_rad_s, hold_arm]`。每条记录使用实际施加的动作，保留双相机、状态、阶段和完成事件。原4维 BC 训练器不能直接处理此数据。VLA 实验额外保存权重 SHA-256、原始／适配动作块、推理耗时与实际执行步数。20 Hz 是仿真记录时间间隔；CPU 模型推理可能使真实等待时间更长。

机械臂目标超出可达范围不再终止实验。每一步先把世界坐标目标换算到底盘局部坐标系，按 `l1+l2` 径向投影回可达区（保留方位与径向／竖直比例），再解 IK。NPZ 同时保存 `arm_target_requested`（约束前）、`arm_target`（约束后实际执行）和 `reach_limited`（该步是否被约束），未触发约束时两者完全相同。投影只限制机械臂能执行的位置，成功判定仍由物理程序独立给出。

## 移动搬运 GPU 训练

从搬运页侧栏打开「训练」，选择成功的 20 Hz、7 维专家示范和模型后提交。训练复用本机 CUDA 环境，后台任务串行占用 GPU，日志会列出设备、加载的轨迹和每轮验证误差。选择至少两条同任务的不同轨迹，系统可留出完整验证轨迹；同配置同种子的重复采集只使用一次。离线误差只覆盖报告列出的验证任务。

移动策略支持状态 BC、双相机 BC、仅用于仿真诊断的特权 BC 和 SmolVLA 移动动作头。SmolVLA 冻结现有视觉编码与语言嵌入，训练本地 7 维动作头。全部模型使用包括底盘线速度和角速度在内的本机动作协议。

训练权重和报告保存在 `datasets/transport_models/<训练任务 ID>`。「用于搬运仿真」会在策略页选中该检查点。推理沿用本机 8772 端口的 GPU 服务；实测请在任务页开始独立仿真，结果按物理程序判定。

## VLA 服务与启动

`vlab/transport_policy.py` 负责服务注册、观测打包、身份与动作检查；独立进程 `integrations/transport_smolvla_server.py` 加载真实 SmolVLA 权重并执行模型推理，不导入仿真或专家控制器。HTTP 使用 `GET /health` 和 `POST /infer`。每个返回包必须匹配实验会话、请求、控制时刻、权重与7维契约；断连、超时或非法动作使本轮失败并保留已有数据，不回退到专家。

默认服务 ID 为 `smolvla-libero`，地址 `http://127.0.0.1:8772`。可在启动后端前通过 `VLAB_TRANSPORT_VLA_URL` 覆盖地址，或通过本机 `work/transport-policies.json` 注册其他服务。页面显示后端实际读取的 `offline/loading/ready/error` 状态。`ready` 只说明服务加载与协议身份检查通过，任务是否成功以仿真结果为准。

首次准备独立推理环境，在项目根目录执行：

```powershell
py -3.13 -m venv .venv-vla
.\.venv-vla\Scripts\python.exe -m pip install torch==2.6.0+cu126 torchvision==0.21.0+cu126 --index-url https://download.pytorch.org/whl/cu126 --no-cache-dir
.\.venv-vla\Scripts\python.exe -m pip install -r requirements-transport-vla.txt
.\.venv-vla\Scripts\python.exe -m pip install --no-deps lerobot==0.4.4
.\.venv-vla\Scripts\python.exe scripts/prepare_transport_vla.py
```

下载脚本从 ModelScope 镜像获取公开的 `lerobot/smolvla_libero` 权重与 `HuggingFaceTB/SmolVLM2-500M-Video-Instruct` 处理器，逐文件检查来源大小与 SHA-256，并保存来源清单。权重放在本机忽略目录 `work/`，不加入源码或实验下载包；不调用 Aholo。SmolVLA 主权重的已知 SHA-256 为 `9a9f6413e42c0f332fccbce9a0dc796af2790f82cf002f791cdbf7e01e1afca8`。

启动推理服务：

```powershell
.\scripts\start_transport_vla.ps1
```

脚本默认在后台以 CUDA 模式启动服务，自动使用支持的 BF16 混合精度，日志保存在 `work/transport-vla.stdout.log` 与 `work/transport-vla.stderr.log`。CUDA 不可用会报错，不自动退回 CPU；已有 CPU 服务也不会被误认为 GPU 就绪。页面显示实际模型设备与显卡名称，精度、CUDA 和 PyTorch 版本记入策略身份。也可在终端直接运行：


保持仿真原 `.venv` 环境不变，在另一个终端启动后端：

```powershell
.\.venv\Scripts\python.exe -m uvicorn vlab.api:app --host 127.0.0.1 --port 8767
```

### 公开权重的实际适配范围

LIBERO 原始7维输出是 XYZ、RPY 和夹爪，与移动任务7维协议含义不同。本适配仅执行 XYZ 与夹爪，保留旋转原始值用于审计，底盘线速度、角速度和保持标志均设为零；旋转值不会被当作车轮速度。状态转换也明确记录局部末端位置、`z + 0.60 m`、向下 TCP 姿态与实测夹爪开度假设。

该权重未针对当前机器人、相机、传送带或移动底盘训练；服务可以提供真实模型动作，但完整移动搬运效果需要实测及后续7维策略训练。历史 `integrations/smolvla.py` 针对旧龙门机构，不能用于声称移动 VLA 已通过。
